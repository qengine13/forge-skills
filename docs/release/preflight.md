# Public collection preflight

Verdict: PROCEED for seven portable skill packages, including the Agent Memory server.
Memory connection and advanced features are opt-in and documented separately.

## Objective

Publish the portable skills in a separate, clearly documented public Git repository. The release
should explain each capability and how to use it, and should prefer the newest model available
within the user's subscription when the host can verify it.

## Boundaries

- Leave any external source collection and its working copies untouched.
- Import selected source files, not repository history, private examples, or caches.
- Preserve existing evidence, permission, memory, and no-overwrite constraints.
- Keep third-party attribution; link external projects rather than claim authorship.
- Carry the source collection's Apache 2.0 license and document modifications.
- Do not claim universal compatibility, measured productivity gains, or automatic latest-model detection.
- Keep private data out of examples, fixtures, comments, and metrics. Examples are fictional.

## Evidence and risks

The instruction packages are checked for portability. Crucible uses host-native authorized
delegation with an offline validator and panel aggregation tool. Model selection follows
verified host capabilities and the user's subscription or explicit choice.

Failure modes: an apparently portable package depends on private tools; a public example leaks
project information; an unknown newest model silently introduces API charges; a vote ignores dissent.

## Gates

- Package metadata parses; every local documentation link resolves.
- Installer exercises isolated destinations, rejects collisions, and preserves existing content.
- Crucible rejects malformed decisions and unresolved dissent.
- Anti-Slop lifecycle exercises clean state, new debt, and downward-only baselines.
- Fresh-context scenario review checks model routing and evidence/authority boundaries.
- Public README renders with readable artwork, working navigation, and per-skill examples.
- GitHub visibility and the exact published revision are read back; hosted checks reported separately.

## Challenge

SELF_CHECK: keep the initial collection focused; no invented full-platform support claims.
Measurement: functional package verification, not statistical productivity claims.
